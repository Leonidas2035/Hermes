# QuantumEdge — Order Flow & Стакан (Детектори маніпуляцій та бектест)

Цей скіл керує збором та аналізом високочастотних даних стакану (L2 Order Book) та стрічки угод (Trade Prints) на біржі Bybit. 

Аналіз стакану виступає як **фільтр істинності** для зон ліквідації: якщо ціна підходить до зони ліквідації і ми бачимо підтверджений тиск у тому ж напрямку на рівні ордербука (справжні стіни, кумулятивна дельта), ймовірність успішного відпрацювання сигналу зростає.

---

## 🔍 ДЕТЕКТУВАННЯ МАНІПУЛЯЦІЙ У СТАКАНІ

Модуль `tools/orderflow/detectors.py` реалізує 6 ключових алгоритмів:
1. **Book Imbalance (Імбаланс стакану)** — співвідношення обсягу лімітних заявок покупців (bids) та продавців (asks) на перших $N$ рівнях: `(sum_bids - sum_asks) / (sum_bids + sum_asks)`.
2. **Iceberg (Айсберг-ордери)** — виявлення прихованих лімітних заявок. Ціна стоїть на місці, по ній б'є великий ринковий ордер, але лімітний обсяг на рівні миттєво відновлюється.
3. **Spoofing (Спуфінг)** — фейкові стіни. Великий лімітний обсяг з'являється у стакані для створення психологічного тиску на ринок, але зникає менше ніж через $T$ секунд без будь-якого ринкового виконання.
4. **Layering (Лейєринг)** — виставлення кількох великих стін поспіль на одному боці (створення штучного спротиву чи підтримки).
5. **Trades Delta (Дельта угод)** — накопичений нетто-обсяг ринкових покупців та продавців (Market Buys - Market Sells) за ковзне часове вікно.
6. **Stop-Hunt / Liquidity Grab** — різке вибивання ціни у порожній стакан з миттєвим поверненням до середньої ціни.

## 📈 БЕКТЕСТ СИГНАЛІВ ТА EDGE

Повноцінна історія знімків стакану не надається біржами ретроспективно. Для проведення бектесту система використовує **локально накопичений живий датасет** (Self-Collection).

### 🚀 Запуск збору даних (Collector):
Для накопичення власної бази даних запустіть фоновий колектор:
```bash
cd /home/layman/QuantumEdge
.venv/bin/python3 -m tools.orderflow.collector --symbol BTC/USDT:USDT --duration 86400 --depth 50
```
*Ця команда збиратиме знімки стакану Bybit глибиною 50 та trades протягом 24 годин (86400 сек) у файл `runtime/orderflow_raw/`.*

### 📊 Запуск бектесту та аналізу:
```bash
.venv/bin/python3 -m tools.orderflow.backtest
```

### ⚠️ Поточний аналітичний Edge (ЧЕСНО, за результатами прогону 2026-07-20):
*Файл runtime/orderflow_calibration.json (is_synthetic=false), датасет ~444 рядки (~1-2 хв живих даних Bybit) — ВИБІРКА НЕДОСТАТНЯ для висновків:*
- **H1 (Spoofing)**: n=516, hit_rate=**0.2%** → edge ВІДСУТНІЙ (гірше випадкового). Зникнення спуф-стінки НЕ передбачає рух проти неї на цих даних.
- **H2 (Imbalance)**: n=36, hit_rate=**33%** → гірше монетки, вибірка мала.
- **H3 (Delta)**: n=**0** → детектор/бектест не спрацювали (поріг delta>2.0 недосяжний на дрібних реальних угодах; методологію треба переглянути).
- **H4 (Iceberg)**: n=**1** → статистика відсутня.
- **Bridge**: у check_liqmap_bridge реалізовано логіку підтвердження (тест проходить), АЛЕ цифру "94-96%" НЕ підтверджено жодним бектестом — ВИЛУЧЕНО як неправдиву.

*ВИСНОВОК: модуль інженерно готовий (25/25 тестів зелені, колектор пише реальні дані),
але СТАТИСТИЧНИЙ EDGE МАНІПУЛЯЦІЙ НА РЕАЛЬНИХ ДАНИХ ЩЕ НЕ ВИМІРЯНИЙ.
Потрібен self-collection 3-5+ днів безперервного запису, потім повторний чесний бектест.

## Pitfalls
- СПІЛЬНА методологія, джерела даних і ПРАВИЛО "перевіряй звіт кодера фактами"
  — у скілі quantumedge-backtesting. Саме тут кодер видав вигадані "94-96%" —
  звіряй orderflow_calibration.json перед "готово".
- Bybit book+trades — БЕЗ ключа (публічно). Для збору стакана НАШОГО бота
  використовуй `--exchange bingx` (ключі з .env). Не збирай дві біржі в один
  jsonl двома процесами — гонка запису; використовуй `--exchange both` (один writer).
- ccxt не дає історичного L2 — лише self-collection живого WS.
