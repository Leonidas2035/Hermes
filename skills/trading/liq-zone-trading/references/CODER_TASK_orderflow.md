## 0. КОНТЕКСТ ПРОЄКТУ

QuantumEdge — приватна торгова система для BTC та XRP на BingX (VST/testnet),
з аналітичним контуром у /home/layman/.hermes/quantumedge_analysis.
У системі ВЖЕ побудовано й перевірено на реальних даних два модулі:
- tools/liqmap/ — карта ліквідацій (зони-магніти). РЕАЛЬНИЙ сигнал: зона ≤1% від
  ціни торкається у 83-95% за 5 днів (BTC, рік даних Bybit).
- tools/sigtest/ — бектест класичних індикаторів. ВИСНОВОК: EMA/MACD/RSI поодинці

  та bb_break (48h, 55.6%).

ІДЕЯ ЦЬОГО ЗАВДАННЯ: стакан (order book) + тейп (trade prints) показують РЕАЛЬНИЙ
потік капіталу й НАМІРИ (ліміти), на відміну від похідних індикаторів. Через стакан
видно маніпуляції (spoofing, layering, iceberg, stop-hunt). Це "фільтр правдивості"
для сигналу з карти ліквідацій: ліквідна зона + справжній (не фейковий) тиск стакана
в тому ж боці = найсильніший сетап.

ЦІЛЬ: модуль tools/orderflow/ із (а) колектором реальних даних, (б) детекторами
маніпуляцій/потоку, (в) бектестом edge, і (г) готовим скілом з реальними числами.

### 3.2. Детектори (tools/orderflow/detectors.py) — на зібраних снепах
Реалізувати й документувати кожен (функція приймає вікно снепів, повертає події):
- **Book imbalance**: (sum_bid_size - sum_ask_size)/(sum_bid+sum_ask) на топ-N.
  Сигнал тиску: >+thresh → вгору, <-thresh → вниз.
- **Iceberg**: лот на рівні з'являється знову після часткового виконання без зміни
  ціни рівня (розмір "поновлюється"). Детект за серією снепів.
- **Spoofing**: великий лот з'являється на рівні, тримається < T сек, зникає БЕЗ
  виконання → фейкова стінка. Вимірювати частку "спуфів" від усіх великих лотів.
- **Layering**: кілька великих стінок поспіль на одному боці (створення "підлоги/стелі").
- **Delta / Order flow**: сума (size*sign) по trades (buy=+, sell=-) у ковзному вікні.
  Позитивна delta при зростанні ціни = справжній тиск (не спуф).
- **Stop-hunt / liquidity grab**: різкий провал book на N% у зону, де немає глибини,
  потім швидке повернення — класичне "збирання" стопів/ліквідацій.

### 3.3. Бектест edge (tools/orderflow/backtest.py) — ЧЕСНИЙ, на зібраному датасеті
Оскільки історичного book немає, бектест ганяється на файлах із 3.1 (self-collected).
Якщо таких ще немає — згенеруй МАЛЕНЬКИЙ синтетичний датасет (документовано) для
smoke-тесту, але виміряний edge рахуй ВИКЛЮЧНО на реальному, коли він з'явиться.
Гіпотези для вимірювання (кожна → win-rate + середній зсув ціни):
- H1: Зникнення спуф-стінки на боці X → ціна йде ПРОТИ фейку (підтверджує маніпуляцію).
- H2: Book imbalance > thresh → ціна рухається в бік імбалансу (протягом M хвилин).
- H3: Сильна позитивна delta + ціна росте → продовження (не розворот).
- H4: Liquidity grab (провал+повернення) → розворот у бік до ліквідної зони.
Вивід: таблиця по кожній гіпотезі (n, win_rate, avg_move, p-value або хоча б довірчий
інтервал). No-lookahead: детектор у момент t використовує лише снепи ≤ t.

### 3.4. Інтеграція з картою ліквідацій (BRIDGE)
Додати в backtest гібридний сигнал: близька зона ліквідації (≤1-2%, з liqmap) +
підтвердження зі стакана (справжній тиск/imbalance/Delta в тому ж боці).
Виміряти: чи гібрид дає ВИЩИЙ win-rate, ніж ліквідаційна зона сама по собі.
Це головна цінність модуля — поєднати два реальних edge в один.
