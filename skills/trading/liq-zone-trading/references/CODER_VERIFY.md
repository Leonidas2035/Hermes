# Чекліст верифікації кодера після здачі модуля (QuantumEdge backtest/analysis)

Кодер (Codex/Claude/Cursor) може видати переконливий звіт із красивими
win-rate, які НЕ існують у жодному файлі результатів. Це траплялось:
orderflow-модуль звітував «bridge 94-96%» та «~55-58%», а в
runtime/orderflow_calibration.json було H1=0.2%, H2=33%, H3=n=0.

## Обов'язкова перевірка (НЕ довіряти звіту):

1. Знайти реальний вихідний файл: `runtime/*_calibration*.json`,
   `runtime/orderflow_calibration.json`, `runtime/liqmap_latest.json`.
   `search_files(target='files', pattern='*calibration*')`.
2. Прочитати його й вивести: `n`, `hit_rate`, `is_synthetic` для кожної гіпотези.
3. Звірити КОЖНУ цифру зі звіту кодера із файлом.
   - Якщо звіт каже «94-96%», а файл має інше (або n<10) → ВІДХИЛИТИ.
   - Якщо звіт посилається на «синтетичний прогін» як на реальність → ВІДХИЛИТИ.
4. Перевірити `is_synthetic: false` — інакше edge виміряний на фейку.
5. Перевірити обсяг даних: `wc -l runtime/orderflow_raw/*.jsonl`.
   Менше ~тисяч рядків / кількох годин = вибірка недійсна, edge не робити заяв.
6. Прогнати тести: `.venv/bin/python3 -m pytest tools/ -q` (мають бути зелені).
7. Скіл оновити РЕАЛЬНИМИ числами з файлу, не зі звіту кодера.

## Анти-патерн (не робити):
- «Кодер каже 25 тестів зелені й edge 94%» → не переносити в скіл без читання JSON.
- Не писати у скіл «підвищує точність до 94-96%» без підтвердження у *_calibration.json.

## Корінь помилки в orderflow (для майбутніх фіксів):
backtest.py брав «ціну майбутнього» по ПЕРШІЙ trade після horizon (шум),
H3_delta мав поріг `delta>2.0` недосяжний на дрібних реальних угодах → n=0.
Методологію треба переробити ПІСЛЯ накопичення великого датасету.
