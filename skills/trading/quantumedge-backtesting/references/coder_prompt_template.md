# Шаблон промпту для кодера (QuantumEdge сигнали)

Перевірений формат, що дав робочий результат (і де кодер схибив — див. п. 4).
Покласти у `references/CODER_TASK.md` цільового скіла.

## Обов'язкові розділи
1. **КОНТЕКСТ ПРОЄКТУ** — що вже є, яка ідея сигналу, навіщо це.
2. **СЕРЕДОВИЩЕ ТА ОБМЕЖЕННЯ** (критично, щоб кодер не спіткнувся):
   - venv: `/home/layman/QuantumEdge/.venv/bin/python3` (НЕ системний)
   - запуск: `cd /home/layman/QuantumEdge && .venv/bin/python3 -m tools.<pkg>.<mod>`
   - мережа: Binance DNS-заблокований; працюють Bybit/OKX; BingX тільки з ключами .env
   - ccxt шум у stderr → глушити grep -vE "RuntimeWarning|...aiohttp..."
   - НЕ escape-ити лапки як \" у .py (tool кидає escape-drift)
3. **ЩО ВЖЕ Є** — вивчи ці файли, дотримуйся стилю (liqmap/sigtest/orderflow).
4. **ЩО ЗРОБИТИ** — нумеровані блоки з конкретними прапорцями/функціями.
5. **КРИТЕРІЇ ПРИЙМАННЯ** — жорсткі, з порогами:
   - hit_rate >= 0.75 І n >= 50 І >=2 режими для "надійного" сигналу
   - РЕАЛЬНІ дані, диск-кеш; якщо датасету нема → ЧЕСНО "edge не виміряний"
   - ЯВНА ЗАБОРОНА вигаданих цифр (під страхом того, що агент перевірить JSON)
6. **ФОРМАТ ЗВІТУ** — українською, з таблицею реальних чисел.
7. **КОРИСНІ КОМАНДИ** + шляхи файлів скіла для оновлення.

## Чому цей шаблон важливий
У цій сесії кодер (orderflow) виконав інженерію 9/10 (25/25 тестів, реальні дані),
АЛЕ у звіті написав "Bridge 94-96%" і "~55-58% на spoofing", яких НЕ БУЛО у
calibration.json (там H1=0.2%, H2=33%, H3=n=0, H4=n=1). Тобто промпт із забороною
фейку НЕ врятував — кодер все одно переніс очікувані числа з синтетики у звіт.
Тому АГЕНТ мусить сам перевірити JSON перед твердженням "готово" (див. SKILL.md).
