 5. WATCHDOG DAEMON — ДЕТАЛЬНА ЛОГІКА
════════════════════════════════════════════════════════════════════════════════

Watchdog — це АВТОНОМНИЙ процес на RTX 4060 (НЕ крон Hermes).
Запускається як systemd user service, працює безперервно.

ЦИКЛ (кожні 5 хвилин, вирівняний по годиннику):
  1. Отримати snapshot з BingX (subprocess → qe_trade.py snapshot)
  2. Витягти: mark_price, legs (entry/size/leverage), open_orders
  3. Прочитати watchdog_state.json → last_price
  4. Порахувати price_move_pct = abs(mark - last_price) / last_price * 100
  5. Fetch 30 свічок 5m через CCXT async → порахувати vol_index
  6. Порахувати buffer_pct = abs(mark - liq_price) / mark * 100
     де liq_price ≈ entry * (1 - 0.95 / leverage) для LONG
  7. Зберегти last_price → watchdog_state.json
  8. Зібрати метрики у промпт → відправити в Ollama (hermes3:8b Q5_K_M)

ПРАВИЛА ПРОБУДЖЕННЯ (wake=true):
  scheduled_5m   → кожні 5 хвилин (поверхневий чек Hermes)
  scheduled_15m  → на :00, :15, :30, :45 (широкий аналіз через agy)
  vol_spike      → vol_index > 0.75 АБО price_move_pct > 1.0%
  liq_alert      → buffer_pct < 3.0% (КРИТИЧНО)

FALLBACK (Ollama недоступна):
  Ті самі правила, але без LLM — чиста математика:
  - minute % 15 == 0 → scheduled_15m
  - vol_index > 0.75 → vol_spike
  - buffer_pct < 3.0 → liq_alert
  - інакше → scheduled_5m з wake=false

ФОРМАТ СИГНАЛУ (watchdog_signal.json):
  {
    "wake": true/false,
    "reason": "scheduled_5m|scheduled_15m|vol_spike|liq_alert",
    "vol_index": 0.0-1.0,
    "price_move_pct": 0.0,
    "buffer_pct": 0.0,
    "note": "пояснення рішення",
    "timestamp_utc": "YYYY-MM-DD HH:MM:SS"
  }

 6. HERMES TRADER — ДЕТАЛЬНА ЛОГІКА
════════════════════════════════════════════════════════════════════════════════

Hermes (tencent/hy3, хмара Nous Research) — головний трейдер системи.
Працює через hermes-gateway.service, комунікує через Telegram.

ЛОГІКА КРОНУ (кожні 5 хвилин):
  1. Прочитати runtime/watchdog_signal.json

  IF wake == false AND reason == scheduled_5m:
    → Запустити trader.py (поверхневий чек)
    → Якщо uPnL змінився > 2% або нові ордери → короткий звіт (3 рядки)
    → Інакше → SILENT (не відповідає)

  IF wake == true:
    IF reason == scheduled_5m:
      → Поверхневий аналіз + корекція SL/грід/харвест
      → Короткий звіт

    IF reason == scheduled_15m OR vol_spike OR liq_alert:
      → ШИРОКИЙ збір даних:
        1. qe_trade.py snapshot (позиції, баланс, ордери)
        2. latest.json (індикатори 1h/15m/5m, book, btc_context, news)
        3. liqmap_latest.json (карта ліквідацій)
      → Сформувати промпт для agy (5 завдань, ≤25 рядків відповіді)
      → Виклик: agy --dangerously-skip-permissions --effort high --print
      → Отримати аналіз від agy
      → САМОСТІЙНО прийняти рішення → trader.py / qe_trade.py
      → Детальний звіт (до 15 рядків)

SMART STOP-LOSS (trader.py → smart_stop_loss):
  1. Параболічний трейлінг: TRAIL_TRIGGER_PCT=0.3%, TRAIL_DIST_PCT=0.5%
  2. Breakeven: BE_PROFIT_PCT=0.05% (мінімальний запас)
  3. Блокування при HIGH orderbook маніпуляції
  4. Затягування при розвороті: RSI>70 + MACD_hist<0 або пробій bid-wall
  5. Ідемпотентність: cancel старого SL → новий (не стекінг)
