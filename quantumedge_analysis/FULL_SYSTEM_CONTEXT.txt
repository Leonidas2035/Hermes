1. АУДИТ УСІХ ФАЙЛІВ ТРЕЙДИНГУ
-------------------------------------------------------------------------------
- [trader.py]: Головний оркестратор торгівлі. Викликається кроном кожні 15хв.
  Збирає дані з market_analysis.py, будує мульти-монетний промпт (XRP, BTC, SOL),
  викликає agy CLI, виконує команди через tools/qe_trade.py та надсилає звіт у Telegram.
- [market_analysis.py]: Аналітичний мозок системи. Збирає мульти-таймфреймні індикатори
  (1h, 15m, 5m), розраховує trend_exhaustion, виявляє hedge_opportunities та генерує
  recovery_signal при наявності накопиченого збитку в recovery_ledger.json. Зберігає
  актуальний зріз у market_analysis.json та latest.json.
- [config.py]: Центр конфігурацій та обмежень. Містить ASSET_STRATEGIES (XRP, SOL, BTC)
  та GLOBAL_LIMITS (MIN_FREE_MARGIN_PCT=0.10, MAX_PARTIAL_LOSS_REDUCTION_PCT=0.50).
- [recovery_ledger.py]: Модуль обліку частково реалізованих збитків (Recovery Ledger).
  Автоматично фіксує частковий збиток у runtime/recovery_ledger.json та надає
  функцію get_recovery_target() для визначення нового Take-Profit при усередненні.
- [tools/qe_trade.py]: CLI виконання ордерів на BingX VST (snapshot, place, market,
  cancel, set_sl, recovery_target, grid, trades) із вбудованими hardware guardrails.
- [market_data.py]: Збирає дані у реальному часі (klines, funding, OI, orderbook) з BingX.
- [indicators.py]: Обчислює математичні індикатори (MACD, BB, RSI, EMA, ATR).
- [.env]: Зберігає API ключі BingX, Telegram bot credentials.
- [trader_state.json]: Зберігає номер циклу, останні біаси та метрики.
- [runtime/recovery_ledger.json]: Файл пам'яті реалізованих збитків для розторговки.
- [runtime/trade_journal.jsonl]: Журнал виконаних ордерів та операцій.

2. RISK GUARDRAILS (PYTHON LEVEL)
-------------------------------------------------------------------------------
Всі ризик-правила зашитi безпосередньо у Python-ядро (tools/qe_trade.py), що фізично
блокує будь-які некоректні команди торгового агента:

1. Margin Lock (Захист Маржі):
   - Перевіряє відношення Free Margin / Total Balance перед відкриттям нової позиції.
   - Якщо вільна маржа < 10%, відкриття нових однонаправлених позицій БЛОКУЄТЬСЯ
     з помилкою MARGIN_PROTECTION_TRIGGERED (дозволено лише контр-позиції для хеджування).

2. No-Loss Lock (Захист від збитків):
   - Забороняє 100% закриття збиткових позицій (uPnL < 0) по маркету з помилкою
     FULL_LOSS_REALIZATION_DENIED.
   - Дозволяє ТІЛЬКИ часткове скорочення (максимум 50% від розміру позиції qty).
   - Автоматично реєструє зафіксований частковий збиток у recovery_ledger.json.

3. ROI Gates (Блокування передчасного профіту):
   - Блокує маркет-закриття та TP-лімітки, якщо досягнутий ROI нижчий за цільовий.
   - SOL: ROI >= 30.0% (Swing strategy).
   - XRP / BTC: ROI >= 1.5% (DCA / Hybrid strategy).

-------------------------------------------------------------------------------
3. COIN-SPECIFIC STRATEGIES (XRP / SOL / BTC)
-------------------------------------------------------------------------------
- XRP (DCA_RECOVERY):
  Робота виключно через лімітні сітки та DCA recovery. Цільовий ROI >= 1.5%.
- SOL (SWING):
  Трендове утримання swing-позицій до досягнення великих імпульсів. Цільовий ROI >= 30.0%.
- BTC (HYBRID):
  Гнучке поєднання DCA, Scalp та динамічного контр-хеджування. Цільовий ROI >= 1.5%.

-------------------------------------------------------------------------------
4. RECOVERY LEDGER LOGIC
-------------------------------------------------------------------------------
При частковому відкушуванні збитку (до 50% qty) сума реалізованого мінусу заноситься
в runtime/recovery_ledger.json під ключем відповідної монети.
При подальшому усередненні на розвороті тренду (сигнал RECOVERY_AVERAGE_DOWN):
Новий TP = EntryPrice + (Accumulated Realized Loss / Position Size) + Min Target ROI.
Це гарантує, що фінальне закриття позиції повністю покриє раніше зафіксований збиток
і принесе чистий прибуток.
